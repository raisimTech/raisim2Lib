Ten-step physics performance per USD

RaiSim on Intel Core Ultra 7 265K versus Newton on GeForce RTX 5070. ANYmal standing and Strandbeest, with one independent robot and world per environment.

Component prices

CPU $339.99: recent Newegg advertised-price scenario, indexed last month. The direct CPU listing is out of stock, so this is not a verified currently buyable quote. GPU $899.99: new MSI Ventus RTX 5070, sold/shipped by Newegg, listed with Add to cart. Checked 15 November 2026; tax excluded. Retail GPU board is a pricing proxy for the measured RTX 5070.

FPS/USD = aggregate world physics steps per second ÷ entire component price. CPU price is not prorated by workers. Host system, RAM, motherboard, power, taxes and licensing are excluded; the GPU also needs a host CPU.

How the price difference affects value

The comparison divides each engine’s throughput by its own component price. A value ratio above 1 favors RaiSim. The ratio is performance per dollar, not the hardware-price ratio or the raw-throughput ratio.

Larger GPU batches

Fresh Newton scaling measurements extend beyond 4,096 worlds using the original ten-step graph and validation protocol. More worlds can improve total throughput until the GPU saturates; after that they increase memory use and lower throughput per world. Missing CPU results are not extrapolated.

See the documentation tables and full scaling JSON for sampled GPU memory and validation results. A conservative memory safeguard stops doubling if process GPU usage exceeds 5,000 MiB; this is not a solver world-count limit.

Measurement details

  • Only ten-step RaiSim scheduling is shown: each worker integrates a world ten times before visiting its next world. Newton uses GPU graphs of ten steps. These are simulation steps, not rendered frames.
  • CPU workers: 1 for one world, 16 for 64 worlds, 20 for 256–4,096 worlds. Worlds are independent, worker-owned and CPU-pinned; the integration inside each world is single-threaded. These worker counts are recorded configurations, not proven optimal.
  • Current RaiSim CPU results: 15 November 2026, FP64. Newton GPU: FP32 SolverMuJoCo / MuJoCo Warp. Results through 1,024 worlds are historical 14 November runs; 4,096 and above were rerun on 15 November for the larger-world sweep. Time steps: ANYmal 2 ms, Strandbeest 1 ms. Setup, warmup, validation and external policy computation are outside timing.
  • CPU results use median elapsed wall time across repeated trials. Single-world cases: 3 processes × 7 trials. Multiworld cases: 2 processes × 5 trials, except ANYmal 4,096/20 discards the first two trials per process under the recorded protocol, scoring 6 of 10 raw trials. Processes ran serially. Timed horizons vary by world count.
  • Physical scenes/controllers were matched, but solvers, precision, constraint formulations and trajectories differ. ANYmal has four contacts/world. Strandbeest historical trajectory means differ: RaiSim approximately 0.959 contacts/world, Newton 0.686–0.700; current RaiSim ending count is one/world. RaiSim merges fixed links (74 bodies); Newton retains them (92). These value ratios do not measure identical numerical work.
  • All 18 measured CPU configurations matched one-step final state hashes and contacts; six extra checks covered partial blocks and uneven worker ranges. This report retains ten primary CPU cases and adds larger GPU batches. No CPU measurement is available above 4,096 worlds.
