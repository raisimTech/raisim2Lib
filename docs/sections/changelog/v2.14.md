# Changelog: v2.14

## v2.14.1 (unreleased)

These fixes come from a full review of RaiSim and rayrai. Unless an entry says otherwise, results in ordinary scenes are bit-identical. A change is only noted where it alters the output of a scene that did not hit the bug.

**RaiSim**

- **Behaviour change:** world XML, URDF, MJCF and inline scene text that does not parse is now a fatal error that names the file, row and column. Before, everything after a typo was dropped silently and the world loaded with objects and settings missing. Text, a stray end tag, a second element or CDATA outside the root element is an error too (comments, processing instructions and whitespace there are still accepted). The vendored TinyXML no longer reads past a multibyte character cut off at the end of the input, and no longer loops forever on it (the CVE-2021-42260 pattern). On Windows, world XML, URDF (with its sensor and actuator files), MJCF (with its includes) and `.rasset` files load from folders whose names the active code page cannot represent; paths are UTF-8 (`raisim::pathFromText()` and `raisim::isUtf8()` in `PathUtils.hpp`), and code-page strings that are not valid UTF-8 still work. Mesh files named by a URDF or MJCF, modules, URDF export and USD import do not handle such folders yet.
- **Behaviour change:** an MJCF `<joint>` without a `type` is a hinge on top-level bodies too, as in MuJoCo; before, it welded the body. MJCF default classes that are defined twice or inherit from themselves are errors instead of a stack overflow. URDF `zaxis` and `axisangle` are normalized, and a zero vector is an error. A URDF material defined after its first use is applied, and a visual's own color no longer changes the shared material. Vector and list attributes accept subnormal numbers, so exported files with tiny values load again. `searchForFile()` with an empty root searches the working directory instead of `/`. `.rscene` `modules` and `jointOrder` lists are unescaped one item at a time. Compound children's `appearance` is exported. USD visual mesh caches no longer collide for prim paths that differ only in `/` versus `_`, and USD texture paths given as `file://` URIs are decoded.
- Checkpoints: restoring a checkpoint taken before the first ray query no longer freezes the ray and lidar caches; before, rays missed bodies that moved after the restore. `setObjectMaterial()` and `setObjectCollisionFilter()` no longer make earlier checkpoints unrestorable. Checkpoints also keep deformable pin targets and the sleep-state ids.
- Sleeping: adding or removing an object, or changing a material or collision filter, wakes only the islands it can affect instead of every island, and `removeObject()` keeps the sleep states of the remaining objects. A sleeping granular pool wakes when a body hits it or its grains move.
- `World::setWorldTime()` shifts the times of live blasts, explosions and projectiles with the clock, so a reset in the middle of a blast no longer replays it. A surface burst placed exactly on the ground loads the bodies around it; its line-of-sight rays used to stop at the ground. `integrateNoContactDetection()` advances projectiles and blasts.
- **Behaviour change:** invalid input is now fatal: a ray or lidar with a non-finite length, direction or pose; collision indices outside [0, 63] in `collision[...]` (`collision[]` means none); Gaussian depth noise with a standard deviation of zero or less; a zero or non-finite quaternion in `setGeneralizedCoordinate()`, `setState()` or `setBaseOrientation()`; a non-orthonormal base rotation matrix; a root joint that is neither FIXED nor FLOATING (`Joint::type` now defaults to FIXED); `setBodyType(DYNAMIC)` on a ground or height map; a malformed OBJ face index; a height-map text file whose header declares more heights than the file holds.
- `ArticulatedSystem::getGeneralizedMomentum()` returns M·u. It used to return memory that was never computed. It is computed when called and is valid before the first step.
- Position-only `solveIK()` overloads ignore `useOrientation`, as documented. `solveIK()` no longer overwrites the solver's velocity scratch, and it cleans contacts exactly when it moves the system. `getContactPointVel()` is zero for the skipped half of a self-contact; before, it read another contact's stale Jacobian.
- **Behaviour change (solver):** articulated self-collision contacts use their pair's true relative normal velocity for restitution. Before, a stale Jacobian could enter it. This changes the results of robots whose links touch each other.
- **Behaviour change (solver):** rolling and spinning friction converge. Their rows used to report an error that never shrank, so every solve with angular friction ran to the stall exit (11 sweeps a step for a ball held on a slope), dropped the warm start of every pin, and let held bodies creep. The rows now report the change of their impulse and are warm-started. A held ball converges in 1 sweep, and a resting pile with rolling friction in about 1 instead of 4. Results change only in scenes with rolling or spinning friction. A contact that loses its normal impulse also releases its angular impulse.
- `World::resetContactSolverWarmStart()` (and `BisectionContactSolver::resetWarmStart()`) clears the solver's warm start, so the steps after `setState()` or a reset do not depend on earlier ones. The default behaviour is unchanged.
- Contact detection:
  - Two small triangles (a few millimetres) or small convex hulls separated by more than 0.1 mm are no longer reported as touching by GJK, unless the GJK search reaches its iteration limit first (then the previous answer is kept). Touching pairs keep their exact contacts.
  - A capsule whose axis passes into a box is pushed out along the axis of least overlap, with its true depth. Before, it was pushed sideways from the box center by one radius whatever the depth.
  - A box–cylinder or box–capsule pair limited to fewer contacts than it has no longer drops a contact that is more than 1 nm deeper than every contact it keeps. In that case it keeps a deepest contact and spreads the others over the contact patch; otherwise the selection is unchanged.
  - A sphere whose center lies on a box face gets that face's normal instead of +x.
  - Degenerate box–box contact sets no longer repeat their deepest point.
  - Mesh–mesh contacts with opposed normals are no longer merged into one.
  - A ray aimed at a height-map cell whose first sample is a hole hits the cell's other triangle.
  - Rays with a zero or non-finite direction or length miss everything instead of turning into +z.
  - The sweep-and-prune broadphase keeps only the pairs that overlap instead of a table of every possible pair: 20,000 bodies used about 1 GB. Pair order is unchanged.
  - Multi-box pruning no longer loses pairs on x86 when a body lies far outside the grid.
- Perlin terrain from a seed is the same with every standard library: macOS, Windows, WebAssembly and source builds against libstdc++ 11 or newer now produce the terrain of the released Linux binaries.
- Deformables: surfaces resampled from a mesh whose triangles differ in size are closed. Before, edges shared by two triangles were split differently, which left cracks, and `Mode::Filled` failed with "requires a closed triangle mesh" on anything but uniform meshes such as cubes. Particles of torus-, cup- or multi-part closed meshes sit inside their surface; their offsets were taken from the centroid, which put some of them outside. `pinVertex()` no longer changes the rest shape. World XML writes a pinned particle's `pin_target` only when it was pinned away from its rest position. Volumes built from negatively oriented tetrahedra get an outward boundary.
- Granular systems: grains on a periodic boundary collide across the seam; before, they overlapped by half a diameter there and were thrown apart. Sleeping and STATIC systems use the world's gravity and (sub)step time step. A grain deep inside a closed mesh is pushed out. Bulk emitting and removing particles is linear in the particle count. Non-finite radii, positions and material values are rejected, a drained system's checkpoint loads, and every system has an object id.
- Fluids: a mesh shape wound inward gets buoyancy and drag; before, all its loads were dropped silently. Each closed part is oriented on its own. A mesh that is not closed is ignored with a warning.
- Sensors: the CPU depth camera casts its rays like the segmentation camera, from the near plane to the far plane along the camera axis, so corner pixels reach the far plane and bodies nearer than the near plane no longer blank pixels. `World::captureDepthCamera()` matches it. A spinning lidar sweeps at most one turn after a jump in time. A tactile contact of zero weight no longer erases the taxel's force.
- `RaisimServer`:
  - Camera, focus and screenshot requests made while no viewer is connected no longer pile up until no viewer can connect. The queue is bounded and is cleared when a frame cannot hold it.
  - **Behaviour change:** a viewer can write the world to a file only after `setViewerWorldExport(true)`.
  - The server deletes the visuals it owns, and `Visuals` and `Chart` have virtual destructors.
  - Viewer camera replies that no longer match the camera are dropped instead of ending the process. Segmentation replies rendered before an object was removed are requested again.
  - A polyline segment between two equal points is sent with an identity rotation instead of NaN.
  - `addVisualHeightMap()` checks names among height maps. Visual height maps reach the viewer under their own name. Removing a visual articulated system or height map updates the viewer.
  - The listening socket no longer blocks the server thread, and `pauseSimulation()` and `stepSimulation()` calls from other threads are no longer lost.
  - The new `PROTOCOL_FEATURE_SENSOR_IMAGE_OFFSET` sends camera image offsets to the viewer.
- Math:
  - **Behaviour change:** `VecDyn(size_t)` is explicit and `v = 1., 2., 3.;` fills a `VecDyn`/`MatDyn` without resizing it. Before, it silently made a one-element vector.
  - **Behaviour change:** matrix expressions other than 1×1 no longer convert to `double`. `+=`, `-=`, `/=` between expressions and `==`/`!=` are element-wise; before, they used element (0,0) only.
  - `dot()` checks the sizes.
  - On macOS the public headers no longer redefine `aligned_alloc`.
- Removed `ArticulatedSystem::getFullDelassusAndTauStar()` (also from raisimPy), a stale copy of the contact Jacobian build.
- New contact-engine functions `meshGeometryEpoch()` and `meshGeometryFingerprint()` in `contact_engine/mesh.h`.
- Class layouts of `World`, `ArticulatedSystem`, `DeformableObject`, `GranularSystem`, `Visuals` and the contact detector changed: rebuild raisimPy and code compiled against older headers.

**Rayrai**

- Hi-Z occlusion culling:
  - On GL below 4.3 (macOS) the Hi-Z build no longer leaves the viewport at a mip size; before, the rest of the frame rendered into a corner.
  - The pyramid is stored as 32-bit float. Half floats culled instances just in front of walls.
  - The pyramid has full mip chains for odd sizes.
  - The culling shader gives up instead of reading thousands of texels for a large near instance.
- Depth and segmentation sensor images honor alpha-mask cutouts, the base-color alpha factor and the albedo UV transform like the color image. Linear depth comes from view-space depth instead of `gl_FragCoord.z`, which is more accurate far away.
- Sensor cameras:
  - They apply their image offset (`x_offset`, `y_offset`), as the CPU cameras do.
  - A near clip of 0 gives a near plane of far × 1e-4 instead of 0.1 m.
  - Segmentation readback ignores the application's pack inversion.
  - Lights and billboard shadows follow the rendering camera instead of the GUI camera.
- GPU lidar no longer reuses the geometry of a removed terrain or mesh, or of a mesh edited in place.
- Shadows:
  - Orthographic cameras with more than one cascade keep their shadows at the screen edges.
  - Cascades follow an off-axis image window.
  - With the opaque depth prepass and simple materials, moving dynamic primitives are no longer replaced by shadow casters.
  - Debug overlays no longer clear lights or compound the weather effect.
- Assets:
  - glTF alpha is no longer applied twice. OPAQUE materials ignore alpha, and occlusion maps are used.
  - Grayscale textures render gray (they were red), and gray+alpha cutouts keep their alpha.
  - Raw embedded texels are no longer red/blue swapped.
  - Line and point primitives are no longer drawn as triangles.
  - An OBJ bump map that is clearly a normal map is used as one.
  - FBX fallback lights are scaled like the meshes.
  - glTF lights are not duplicated, and cyclic node graphs are rejected.
  - Materials with their own wrap mode no longer change shared textures.
  - Edited or newly added texture files are picked up.
  - On Windows, model and texture paths with characters outside the code page load.
- Mesh visuals loaded in the background get automatic LODs. Mesh LOD caches validate their contents and live in a per-user cache folder; their version changed, so they are rebuilt once. Async LOD preparation survives worker exceptions.
- Picking ids of objects and visuals no longer collide, and visuals outside their visibility range cannot be picked. `setGroundPatternResourcePath()` updates an existing ground. The static scene layer keeps HDR values. Probe filter sample counts are clamped to 1024.

**TCP viewer**

- Stopping a video recording, or quitting, no longer hangs when an example was started while recording: the ffmpeg pipe and the viewer's sockets are no longer inherited by child processes. On Windows, recording and Encode To Video work again (the quoted command line was mangled). Encode To Video runs in the background and never overwrites an existing file.
- The viewer rejects malformed frames (with an oversized sensor or instance count, or a truncated section) instead of allocating without bound, or half-applying them. A parse error ends the session. Legacy layout guesses were removed.
- Visual height maps are drawn at their real height and pose. Collision-body toggling keeps mesh colors. Inspector joint sliders use the right joint limits. Depth and segmentation previews are upright. Examples that never announce a port stop after 60 s, and beacons from other computers are ignored. Pane layouts and settings values containing `#` survive a reload. Replay speed is clamped.
- On Windows, dropped files, the file browser, resource folders, screenshots and videos handle non-ASCII paths. Resource folders saved with non-ASCII names by an older viewer have to be added again.
- Sends time out after 5 s on a stalled server.

## v2.14.0 (2026-11-08)

**RaiSim**

- Explosions and projectiles ([Explosions and Projectiles](../Explosions.md)). `World::addExplosion()` sets off a TNT-equivalent charge whose blast wave spreads at the Rankine–Hugoniot shock speed and loads every dynamic body it reaches, panel by panel, with the incident, reflected and dynamic pressures of a Friedlander pulse fitted to Kinney and Graham's free-air curves; the load is integrated over each step exactly, so bodies gain the same momentum at any time step. Bodies hidden from the charge take only the wave that wraps around them, surface bursts load like heavier free-air charges, and craters lower heightmaps and deformable soil. `World::addProjectile()` flies shells, bullets and grenades under gravity and quadratic drag relative to the ambient air (whose velocity is the wind) or the liquid of a fluid volume (its sampled or wavy surface and current, where it has a sampler or waves), sweeps each step with a ray so fast rounds hit thin plates, hands the body it hits the impulse of a perfectly inelastic impact at that point (from its velocity relative to the point and the mass the body presents there, rotation and joints included; rounds that hit a body in the same step take turns), and, if explosive, detonates on impact or on a time fuse. `World::getProjectileLaunches()` lists recent launches, whatever became of them. Blasts, projectiles and the event lists are captured in checkpoints. The model is checked against Kingery–Bulmash values (IATG 01.80) by 37 new tests; the new `explosion` benchmark compares it with MuJoCo.
- `RayCollisionItem::getNormal()` gives the surface normal at a ray hit.
- Ray tests (`rayTest()`, lidars, projectiles and the blast's line of sight) are faster in worlds with many static bodies: the static bodies keep their BVH while none of them moves, and only the moving bodies are sorted into a tree again when bodies move. Results are bit-identical. A projectile volley over 1000 static bodies steps 34% faster; in the tank survival game, rebuilding the BVH took a sixth of each battle step and now takes 2%.
- `Mat`'s initializer-list constructor reports an oversized list out of line, so the constructor inlines without link-time optimization: RaiSim in the WebAssembly SDK steps as fast as with LTO (a contact-heavy scene went from 649 to 358 µs per step).
- raisimPy binds explosions, projectiles and the `blast` model (`raisimpy.blast.wave()`).
- raisimPy's rayrai module binds the explosion effects (`ExplosionEffectSettings`, `ExplosionEffect`, `FireEffect`, `RayraiWindow.addExplosionEffect()`, `addFireEffect()`, `setExplosionEffectSettings()`, `clearExplosionEffects()`, `activeExplosionEffectCount()`, `prepareExplosionEffects()`), the physics snapshot's `explosions`, `projectiles`, `projectileHits` and `wind`, and `InstancedVisuals.setFoliageShadowMeshLodPixelError()`. Its bindings had not been generated again after these rayrai headers changed, so the header inventory test failed.
- `.rscene` import copies the values that hold no `%` escape as they are instead of byte by byte: the forest scene (2,425 objects) parses in 58 ms instead of 66 ms, and a world built from it loads about 10% faster, with the same scene.
- Numbers in RaiSim's files (`.rscene`, world XML, URDF, MJCF) are converted with exact integer arithmetic (Clinger's fast path, then the Eisel–Lemire algorithm) when they have up to 19 significant digits and the default rounding mode is set, and with the C library otherwise. The result is the same double the C library gives, bit for bit. The forest `.rscene` (860,000 numbers) parses in 42 ms instead of 58 ms and a world built from it loads 22% faster; URDF robots load 4–5% faster.
- URDF and XML files parse faster: the XML reader counts the columns of a run of plain characters at once when it records where each element starts, and gives the same line and column numbers in messages. Together with the faster numbers, ANYmal's URDF loads in 0.21 ms instead of 0.25 ms and Atlas's in 0.53 ms instead of 0.59 ms.
- An articulated system whose state is set every step (a robot moved through recorded poses, an arm driven kinematically) keeps the storage of its contact Jacobians instead of allocating it again in the next step, and the internal contacts past `getAllowedNumberOfInternalContactsBetweenTwoBodies()` are marked without sorting them a second time. A Kinova arm on a table, set to a new pose every step, steps 7% faster, with the same results.
- Fixed: an articulated system that had come to rest and fallen asleep ignored new PD targets and gains, so a parked robot stayed put however its joints were commanded until something else woke it. `setPdTarget()`, `setPTarget()`, `setDTarget()`, `setPGains()`, `setDGains()`, `setPdGains()` and `setControlMode()` wake it when they change a value, as a force does; setting the same values again lets it sleep.
- The contact solver looks up last step's impulses (its warm start) in a flat open-addressing table instead of `std::unordered_map`, which divided by a prime on every lookup: primitive-heavy scenes step 1–3% faster. Simulation results are bit-identical.
- A box, capsule or cylinder that hangs over the edge of a height map and touches nothing no longer tests all 16384 interior samples of the last recovery sweep every step. The samples are grouped into fixed spatial bins once, and a bin whose lowest point clears the terrain under the shape is skipped as a whole. The terrain case of the tracked-robot benchmark, where robots drive off the map edge, steps 7% faster. Simulation results are bit-identical.
- **Behaviour change:** spherical joints have Coulomb friction ([Joint Damping and Friction](../articulated_system/JointDampingAndFriction.md#spherical-joints)). The URDF `<dynamics friction>` of a spherical joint (and the PhysX `jointFriction` of a USD spherical joint) used to be ignored. It now bounds the magnitude of the joint's friction torque, the same in every direction: the joint is held at rest while the other torques on it stay below the bound, and otherwise braked with the bound against its relative angular velocity. A spinning joint slows down about a fixed axis, and a pendulum comes to rest anywhere inside its friction cone. The friction is solved with the contacts, the joint limits and the friction of the other joints; in a closed loop it acts only in the directions the loop lets the joint turn, and the loop's forces carry the rest. Robots without friction on spherical joints simulate as before, bit for bit. The new `testJointFriction` checks the step equation of every friction case against the model, and the new `joint_friction` benchmark times a 12-link chain of spherical joints and a humanoid ragdoll, and checks the chain's friction torques. The new example [Spherical Joint Friction](../examples/rayrai/rayrai_spherical_joint_friction.md) releases three spherical pendulums with no, a little and a lot of friction. Friction on the 12 spherical joints of a hanging chain adds 22 µs to its 3.4 µs step while they slide, and a humanoid ragdoll with friction on its 8 spherical and 4 revolute joints steps in 86–96 µs instead of 26 µs on the ground. With the default contact-solver settings, strongly coupled joints that mostly stick (the chain with 1 Nm of friction) leave some sliding joints braked by as little as 55% of the bound; with a tight solver tolerance they converge to the bound.
- Fixed: RaiSim-sourced sensors drifted off their update grid. An IMU added its period to its next deadline and compared the sum with the world time. The rounding error of the sum grew with every sample, so about once per doubling of the simulated time one sample came a step late or a step early: a 500 Hz IMU at 2000 Hz slipped at 0.57 s, 2.3 s, 5.7 s and so on, or at 10.2 s, 19.4 s, 37.8 s and so on with the world time set to whole nanoseconds every step. A world clock that disagreed with the time step (whole nanoseconds at 3000 Hz) also slipped it a step every 333 s, and delayed a 2 ms latency to seven steps. Depth cameras and LiDARs were updated one period after their last update, rounded up to a step, so a 30 Hz camera at 1000 Hz ran at 29.4 Hz. All of them now take the deadlines of a fixed grid `1 / update_rate` apart at the first step that reaches each one, counting physics time in time steps rather than world time ([Update timing](../Sensors.md#update-timing)). The 30 Hz camera is updated 34, 33 and 33 steps apart in turn, 30 times a second, and the IMU every fourth step without slipping. IMU latency is counted in time steps too, and a latency just over a whole number of steps no longer drops to that number after a few minutes (2 ms and 1 ps at 1000 Hz took two steps instead of three after 140 s). The world time stamps the samples; a spinning LiDAR's head still turns by the world time between updates. Setting it back by more than a step still starts a new episode with an update at once. A new update rate now restarts the grid with an update at once for cameras and LiDARs, as it already did for IMUs. `isUpdateDue()` and `setUpdateTimeStamp()` still schedule sensors with a `MANUAL` source. `detail::headerLayoutStamp()` covers `Sensor` and `InertialMeasurementUnit`, whose layouts changed, so code compiled against older headers fails at `World` construction instead of misreading sensors. Counting the grid exactly costs an IMU 4 to 15 ns more per step (74 to 78 ns for an ideal IMU, 170 to 185 ns with noise, filters and latency; `imu_sensor_benchmark`).
- Fixed: viewer-rendered `MANUAL` RGB/depth cameras retain their nominal sampling grid, so a 30 Hz camera at 1000 Hz averages 30 Hz with 33/34-step intervals instead of 29.4 Hz. Requests use compensated physics time for world and visual-only robots, and replies acknowledge the captured acquisition time. Delayed or duplicate replies retain the grid, and clock edits, rate/source changes and checkpoint restoration follow the rules in [Update timing](../Sensors.md#update-timing). New regressions cover the server round trip and the 3000 Hz nanosecond-correction case; `manual_camera_benchmark` checks RGB/depth cadence at 30, 300 and 500 Hz.
- Segmentation cameras ([Segmentation camera](../Sensors.md#segmentation-camera)). `raisim::SegmentationCamera` reports what each pixel sees in up to three `int32` images: the world index of the object, the body of that object and its semantic label, with -1 where nothing is hit. `semantic`, `instance` and `panoptic` cameras fill the label image, the object and body images, or all three. `Object::setSegmentationLabel()` labels an object, `ArticulatedSystem::setBodySegmentationLabel()` one body, and `World::addSegmentationClass()` names labels. URDF sensors of `type="segmentation"`, world XML (`segmentation_label`, `segmentation_class`, `<body_segmentation>`, `<segmentation_classes>`), `.rscene` `semanticClass` keys, Engine 2 scenes and checkpoints carry the cameras, labels and class names. A `MANUAL` camera is rendered by rayrai or by a connected `rayrai_tcp_viewer` on the same sampling grid as RGB and depth cameras; with the `RAISIM` source, `update()` ray-casts the collision bodies. `SegmentationCamera::colorize()` colors an id image for display. raisimPy binds the camera, the labels and the class table, with images as `(height, width)` `int32` arrays. The new `segmentation_camera` benchmark times the ray cast.
- Segmentation labels: `Object::setSegmentationLabel()`, `ArticulatedSystem::setBodySegmentationLabel()` and `clearBodySegmentationLabels()`, and class names with `World::addSegmentationClass()`, `getSegmentationClassName()` and `setSegmentationClassName()`. World XML files, checkpoints and the `.rscene` `semanticClass` key carry them.
- `SegmentationCamera::colorize()` colors id images for display.
- raisimPy binds the segmentation camera (`(H, W)` `int32` NumPy images), the labels and the class names.
- Fixed: changing a camera's image while a TCP viewer was connected (`RGBCamera::setProperties()`, a `DepthCamera`'s properties followed by `updateRayDirections()`, or `SegmentationCamera::setProperties()`) left the viewer rendering the old image size or type; the server rejected its reply and dropped the connection. The server now sends the new properties before the viewer renders the camera again, for robots in the world and visual articulated systems alike. An image the viewer was already rendering when the properties changed is dropped without counting as a sample, so the camera is requested again with its new properties; a segmentation reply carries the segmentation type it was rendered with for this.
- Fixed: the TCP viewer read a visual articulated system (`addVisualArticulatedSystem()`) with fewer than two visuals, such as a robot with one mesh or a camera rig without geometry, as a visual object and failed to parse the frame, and it rejected a frame whose first record was a visual articulated system. With the new protocol feature `PROTOCOL_FEATURE_VISUAL_ARTICULATED_TYPE` they arrive with an object type of their own ([Protocol](../RaisimServer.md)); viewers that do not negotiate it receive the old records. As with every new feature bit, a viewer of this release needs a server of this release: a server closes the connection of a viewer that sets a bit it does not know.

**Rayrai**

- Rayrai draws the world's explosions and projectiles ([Explosion effects](../rayrai/Explosions.md)): a ray-marched fireball that cools into billowing, sun-lit smoke drifting with the wind, sparks, debris and dust, a flash light and scorch decals, muzzle flashes, tracers and impact sparks. `addExplosionEffect()` draws an explosion that is not in the world, and `setExplosionEffectSettings()` tunes them. They follow physics snapshots and the world clock, so they pause and rewind with the simulation, and each effect is drawn from the event that caused it, so replays look the same. The flash light and scorch marks join the window's lights and decals only during a render, leaving the application's lists unchanged. `prepareExplosionEffects()` compiles their shaders ahead of the first explosion.
- Explosions look photoreal in scenes lit by a strong sun: smoke, dust and debris are lit like the scene's meshes (the main light over pi). Ground bursts throw up a column of earth and dust under the smoke, dust that rolls out along the ground, and clods of earth that arc out and fall back; bursts at a water surface throw up spray and mist. `ExplosionEffectSettings::smokeColor` and `dustColor` color the world's explosions (soil, sand, snow or concrete dust), `ExplosionEffect` gains `dustColor` and `inWater`, and particles fade softly where they meet the scene.
- Explosion fireballs and smoke are no longer round: each is a heap of uneven lobes laid out anew for every explosion, bent by low-frequency noise, with ragged, wispy rims eaten by finer noise, and the smoke heaps up as it rises. The sun's shadow inside the smoke takes two samples instead of three; an explosion-heavy frame costs about 0.4 ms more on an RTX 5070.
- `addFireEffect()` starts a fire (`FireEffect`): flickering flames and a column of black smoke drifting with the wind, made of particles, for burning wrecks and fuel spills.
- A rayrai muzzle flash is sized by the cube root of its projectile's kinetic energy: a machine gun's is a sixth of a tank gun's, so a burst no longer piles up into a white cloud. Shells of a megajoule and more look as before.
- After `prepareExplosionEffects()`, foliage drawn with rayrai's sun-only programs also links the programs an explosion's light selects, so the first explosion no longer compiles three shaders mid-game (a 0.5 s stall in the browser); the image is unchanged.
- Fixed: destroying an instanced batch whose LODs were still being prepared waited for the workers; in the browser, when they needed a new thread, the page froze for good (Tank Survival, choosing a level while the menu's models still loaded). The workers now finish on their own; on the desktop a window waits for them when it is destroyed.
- `InstancedVisuals::setFoliageShadowMeshLodPixelError()` sets the mesh-LOD error budget of foliage in shadow maps apart from the visible one (`setFoliageMeshLodPixelError()` sets both until it is used), so trees can keep finer meshes on screen without paying for them in every shadow cascade.
- Rayrai does less work for the same image: a river's bed is read back from the GPU only after it changes, the sky that water reflects is drawn into its cubemap again only when the sky changes (a generated weather sky included), and all explosion volumes of a frame take one instanced draw instead of one draw each. Shaders keep the locations of up to 128 uniform names (from 32), and instanced passes classify each foliage batch once. `WaterDiagnostics::skyCaptures` counts the sky captures. On the desktop, Tank Survival's levels render 7–13% faster (RTX 5070, 1600×900); simulation and images are unchanged.
- Explosion smoke and dust fetch their noise only where it can change them (past the reach of a cloud's lobes, its dust column or the dust rolling along the ground, no noise brings smoke in), for the same image: looking into the dust of a dozen ground bursts, the volumes draw 22% faster on an RTX 5070 at 1600×900 (13.4 to 10.4 ms), and Tank Survival's dustiest frame (Frozen Ridge under a smoke screen and mortar fire) renders in 11.1 ms instead of 15.7. The new `rayrai_explosion_volume_benchmark` measures it.
- An explosion effect added with `addExplosionEffect()` before a window's first frame is drawn: it starts by the world's clock, where it used to start by the wall clock and be dropped at the first render.
- Explosion fire and smoke are much cheaper to draw and less grainy.
  - They are marched at half the image's width and height (`ExplosionEffectSettings::volumeDownsample`, 1 to 4, default 2) and blended into the image along its depth. Each marched pixel stops at the nearest scene depth it covers, and each image pixel blends the four by four nearest marched pixels whose depth matches its own, so smoke behind a nearer object does not spill over its edges or over objects thinner than a marched pixel.
  - Each ray takes about `marchSteps` steps across the volume, so rays that cross only its edge take fewer.
  - Neighbouring marched pixels start at interleaved fractions of a step, which the blend averages into smooth smoke instead of grain.
  - A cloud's lobes take one square root instead of seven, for the same image.
  - On an RTX 5070 at 1600×900, a smoke screen across the view adds 0.85 ms to the frame instead of 3.7 ms. Looking into the dust of a dozen ground bursts adds 1.8 ms instead of 10.4 ms, and 0.9 ms at a third of the resolution. `rayrai_explosion_volume_benchmark` reports both, and takes `--downsample=N`.
  - Tank Survival marches at a third of the resolution (half at Ultra). Its smoke screens and barrages no longer slow the game down on smaller GPUs and high-density screens, where the full-resolution march grew with the pixel count.
- Fixed: explosions and fires could go undrawn where the window reuses what it drew before. An effect added with `addExplosionEffect()` or `addFireEffect()` to a scene in which nothing moved, or an explosion set off in such a world, showed the cached picture of the unchanged scene; behind a moving body, a scene whose static part comes from a cached layer drew no fire and smoke. While effects are in progress the window now draws every frame in full.
- Fixed: a camera rendering a small static world with `renderWithExternalCamera()` and a fixed shadow center, moved away for one frame and back, kept showing the frame from where it had been. A cached frame is reused only while the camera has not moved since its last frame.
- Fixed: under a low sun, surfaces in the far shadow cascades shadowed themselves: ground, rocks and vehicles went dark in patches that appeared and vanished as the camera moved (Tank Survival's Frozen Ridge, under a 17° sun). A far cascade's texels cover several times the ground of the first one's, and every cascade used the depth bias set for the first. Each farther cascade now moves its receivers along their normals by its filter footprint plus one texel, times how much wider its texels are than the first cascade's, and fits its map with that margin. Shadows stay attached to the objects that cast them (a larger depth bias would have pushed far shadows up to a metre away from their casters), and the first cascade is unchanged.
- New example: `rayrai_tank_survival`, the [Tank Survival](../examples/rayrai/rayrai_tank_survival.md) game built from the same source as its web page, so the desktop and the browser play and look the same (the browser no longer plants different trees).
- New example: [Explosion and Projectile](../examples/rayrai/rayrai_explosion_projectile.md), the least code that uses projectiles and explosions: a gun fires a solid round and an explosive shell at a wall of crates, and a charge goes off beside it.
- `RayraiWindow::renderSegmentation()` renders the object, body and label of every pixel into an integer target of the camera, drawing the geometry of `renderDepthPlaneDistance()` so segmentation and depth images of a camera agree pixel for pixel; `Camera::getRawImage()` fills a `SegmentationCamera` and `Camera::readSegmentation()` reads the images into buffers of your own. Visuals write the ids of `Visuals::setSegmentationIds()`. Fisheye depth and segmentation images are now resampled through the lens like color images, instead of being drawn with the pinhole projection. The TCP viewer renders the segmentation cameras of a server's robots, shows a colored preview and marks their frustums. raisimPy's rayrai module binds the segmentation renders and readbacks. The new example [Segmentation Camera](../examples/rayrai/rayrai_segmentation_camera.md) shows a color image and a segmentation image of one camera side by side.
- **Behaviour change:** a fisheye camera's `renderDepthPlaneDistance()` depth is remapped through the lens like its color image, so `DepthCamera::depthToPointCloud()` reconstructs its points. It used to stay rectilinear.

**Browser (WebAssembly)**

- The full `webassembly-<version>.zip` release now includes the SDK in `sdk/`, so the same download can run the demos and build custom dependent packages. Packaging requires and audits both parts before any upload. SDK files are frozen at audit time, private files and unexpected WASM sections are rejected, and built-in Rayrai shader implementation headers are omitted while the public `Shader.hpp` interface remains available. The standalone SDK archive remains available.
- The [WebAssembly SDK](../WebAssemblySdk.md) lets you build browser programs of your own on RaiSim and Rayrai. It holds prebuilt libraries, headers, the CMake packages `raisim` and `rayrai`, and a page runtime, for Emscripten 4.0.0. The libraries are WebAssembly objects linked into one object per library. They carry no source, no LLVM bitcode and no debug names, and a packaging audit enforces this. `rayrai_add_web_app()` turns an ordinary Rayrai program into a web page; `raisim::raisim` alone runs under Node.js. Releases publish `webassembly-sdk-<version>.zip`, and a local `linux_install.sh` unpacks it in `raisim2Lib/wasm/sdk`.
- The WebAssembly license has a new clause 4 for programs built with the SDK:
  - Only academic users may distribute such programs, and only for academic purposes.
  - They distribute the program, never RaiSim or Rayrai themselves.
  - Every distribution must state clearly that the program is built with RaiSim and Rayrai under the license, and include it and the third-party notices.

  `rayrai_add_web_app()` and the new `raisim_web_add_license()` place the license and notices next to a program, and the generated page shows the notice.
- `rayrai_add_web_app()` takes `ASSETS` (files and folders the page downloads into the program's file system before `main()`, each fetched and cached on its own, so a game's assets need not fit in one file), and `DESCRIPTION`, `URL` and `IMAGE`, which write the Open Graph and Twitter Card tags that make a shared link show as a card with a picture.
- The page runtime of `rayrai_add_web_app()` downloads the program's WebAssembly and its assets together, with a progress bar, and keeps the shader programs its WebGPU backend compiles in the browser (Cache Storage, per build of the program): a second visit to Tank Survival reaches smooth play about 40% sooner. Assets that arrive after the program is instantiated go straight into its file system. The asset manifest holds the WebAssembly's size, so the bar is exact when the host compresses it, and a page whose sizes are unknown shows an indeterminate bar.
- A page made by `rayrai_add_web_app()` writes its assets into the program's file system in one copy each instead of byte by byte (Emscripten's `FS.writeFile`): Tank Survival's page starts its program 1.6 s sooner on every visit (2.1 s to 0.5 s) and reaches a smooth menu 1.7 s sooner. The program exports `_malloc`, `_free`, `_rayrai_web_write_file` and `wasmMemory` for it.

- Camera and sensor readbacks are much cheaper: readbacks wait once for the GPU instead of twice, readbacks in the stored format are plain copies instead of per-channel conversions, `glReadPixels` into client memory copies the mapped rows straight into WebAssembly memory, and pixel-pack copies with 256-byte rows stay on the GPU.
